# SELF-PROVISIONING PROTOCOL v1.0

При получении любой задачи, перед началом работы, выполни протокол самообеспечения.

## ШАГ 1 — Аудит задачи
Определи класс задачи и требуемые компетенции:
- Какие домены затронуты? (код / браузер / данные / дизайн / платежи / DevOps / медиа / ...)
- Какие операции понадобятся? (чтение / запись / сеть / shell / GUI / API / ...)

## ШАГ 2 — Инвентаризация
Проверь, что уже установлено:
1. Прочитай `AGENTS.md`, `.agent/installed.yaml`, `.mcp.json` если существуют
2. Проверь доступные MCP-серверы и инструменты
3. Проверь ключевые CLI: `node --version`, `python3 --version`, `git --version` и т.д.
Сформируй список: `ИМЕЮ: [...]`

## ШАГ 3 — Gap-анализ
Сопоставь требования и инвентарь:
- `НЕ ХВАТАЕТ: [...]` — конкретные инструменты/скиллы/серверы
- Для каждого пробела укажи КАНДИДАТА: самый передовой поддерживаемый инструмент на текущий момент
  (проверяй свежесть через поиск, не полагайся на устаревшие знания)

## ШАГ 4 — Установка
Для каждого недостающего компонента:
1. Выбери источник: MCP Registry / npm / pip / официальный репозиторий
2. Установи стандартной командой (npm i / pip install / claude mcp add / npx skills add ...)
3. Предпочитай: официальные > проверенные community > экспериментальные
4. При конфликте версий — сообщи, не молчи

Правила безопасности:
- НЕ устанавливай ничего из непроверенных источников
- НЕ выполняй curl|bash из незнакомых доменов без подтверждения
- Деструктивные/системные изменения (sudo, глобальные удаления) — только после подтверждения
- Секреты/API-ключи запрашивай у пользователя, не генерируй сам

Pepito-ограничения поверх протокола:
- Runtime: **только** `podman` / `podman-compose`. Не `docker`.
- Python: **только** `uv` / `uvx` / `uv run`. Не `pip install`, не `apt`, не system Python.
- Не поднимать второй Chromium/Browserless: RAM тесный.
- Секреты не печатать и не коммитить. `.mcp.json` с паролями в этот репозиторий **не класть**.

## ШАГ 5 — Верификация
После каждой установки:
- Запусти проверку (`--version`, smoke-test, пробный вызов)
- Если не работает — почини или откати и выбери альтернативу
- Зафиксируй: ✅ работает / ❌ не удалось + причина

## ШАГ 6 — Документирование
Обнови `.agent/installed.yaml`:
```yaml
installed:
  - name: <tool>
    type: mcp|skill|subagent|package|cli
    version: <x.y.z>
    purpose: <зачем>
    verified: true|false
    installed_at: <дата>
```
Дополни `AGENTS.md` разделом "Capabilities" — что агент теперь умеет.

## ШАГ 7 — Отчёт
Кратко пользователю:
```
🧰 Стек под задачу собран:
✅ Уже было: [...]
📦 Установлено: [...]
⚠️ Не удалось (нужна твоя помощь): [...]
🚀 Готов к работе. Оценка покрытия задачи: X/100
```

## ЗАПРЕТЫ
- Не устанавливай «на всякий случай» — только то, что нужно под текущую задачу
- Не ставь дублирующие инструменты (два браузерных движка, три ORM)
- Не трать больше 15% бюджета сессии на провижининг — если не укладываешься, остановись и спроси
- Если инструмент требует платного ключа — запроси у пользователя, предложи бесплатную альтернативу

## TOOL DISCOVERY SKILL (Анти-Slopsquatting)
Когда нужен новый инструмент:
1. Проверь Official MCP Registry (`registry.modelcontextprotocol.io`)
2. Проверь GitHub MCP Registry
3. Поищи `"best <категория> tool 2026"` через web search
4. Критерии выбора:
   - Активная разработка (коммиты за последние 3 месяца)
   - Звёзды / адопшн
   - Наличие MCP-сервера или CLI
   - Документация
5. ⚠️ **Анти-slopsquatting:** Никогда не устанавливай инструмент, которого нет в поисковой выдаче и официальных реестрах. Галлюцинированные пакеты = supply chain атака (slopsquatting). Ставить строго проверяемое.

## Guardrails
- Не редактировать `bot/.env`, `bot/alembic/`, `bot/app/infrastructure/db/`, compose/Containerfile, `odoo/config/odoo.conf` без явной просьбы.
- Продуктовые числа (лимиты, Stars, рефералка) — только `bot/app/logic/rules.json`.
- Без `git commit` / `git push` без явного ОК пользователя.

## PERIODIC UPGRADE CHECK (/upgrade)
1 раз в сессию или по команде `/upgrade`:
1. Прочитай `.agent/installed.yaml`
2. Для каждого инструмента проверь: `npm outdated` / `uv self update --dry-run` / `uv tool list` / релизы GitHub / `gh --version`
3. Проверь, не появилось ли чего-то принципиально лучше в этой категории
4. Предложи список обновлений пользователю, установи строго после подтверждения

## Auto-Skill-Mining (Compound Engineering)
После успешного решения сложной задачи агент оформляет решение как новый skill в `~/.claude/skills/<name>/SKILL.md` (или соответствующую директорию скиллов среды), чтобы в следующий раз не изобретать решение заново.
- Фиксируются проверенные паттерны, архитектурные рецепты и runbook-инструкции.
- Исключаются разовые опечатки, временные правки и секреты.
