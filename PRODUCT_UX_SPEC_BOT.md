> Область: только `bot/` (Telegram-бот `@pepitopetbot` и его API для WebApp).
> Odoo и Android не трогаем, кроме уже существующих вызовов каталога.
> Источник: аудит кода и БД от 2026-11-01 и 3 раунда интервью с владельцем.

## 1. Решения владельца

| Тема | Решение |
|---|---|
| Free-лимит | **3 текстовых ИИ-ответа в день** по местному времени + **1 бесплатная проба** разбора фото/голоса за всё время. Лимит списывается только за успешный ответ. |
| Продажи | **Автоподписка Telegram Stars** (30 дней, `subscription_period`), **пакеты 3 и 12 мес** (Stars, разово), **рубли через Т-Банк** |
| Триал | **Нет.** Бонусные дни Premium только за рефералов (механика уже есть) |
| Пейволл | **Инвойс в 1 тап** прямо в ответе при упоре в лимит, **строка «осталось N из 3»** под бесплатными ответами |
| Паспорт | **Паспорт + долгосрочная память ИИ**, **несколько собак** (Free: 1, Premium: до 3) |
| Здоровье | **Прививки, клещи/блохи, глисты** с умными пушами, **сезонные пуши** |
| Трекер | **Стрики + заморозка**, **прогулки с длительностью**, **ачивки**, **недельный отчёт** по местному времени |
| Медиа/карточки | **Строгий Pydantic** для фото/голоса + **PNG 1080×1920 из HTML/CSS** лёгким рендером без браузера |
| Онбординг | **4 шага кнопками + опциональное фото** вместо ИИ-диалога |
| Меню | **Single-Window** (одно живое окно через edit), **сообщения пользователя не удалять**, **кнопки ≤ 14 символов** |
| Reply-клавиатура | Не выбрано, оставляем как есть: бот её не показывает и снимает `ReplyKeyboardRemove` |
| Тон | **«Ты»**, живой кинолог, все RU-тексты и промпты проходят чек-лист humanizer-ru |
| Деплой | **Podman Quadlet + systemd** |

## 2. Фаза P0-SEC: инцидент безопасности (до любой разработки)

**Факт:** в `pepito-bot_redis_1` с 2026-10-26 работает майнер XMRig (`/tmp/.sys`, пул `pool.supportxmr.com`, ~85% CPU, uid 999 на хосте). Как зашли:
- `bot/podman-compose.yml` публикует `6379` и `5432` на `0.0.0.0`;
- у Redis нет пароля;
- пароль Postgres `pepito_pass` закоммичен, репо `Vangog4/pepiti` **публичный**;
- `ufw` выключен.

В логах Postgres 95 неудачных попыток входа, и брутфорс продолжается. Ошибки `database "pepito" does not exist` говорят о том, что аутентификация как минимум для одного логина проходит.

Владелец решил: «только отчёт». Шаги ниже выполняются вручную или после отдельного «ОК».

1. Сохранить улики: `podman cp pepito-bot_redis_1:/tmp <dir>`, затем `podman logs pepito-bot_db_1 > <dir>/pg.log`.
2. `podman stop pepito-bot_redis_1`. Это гасит майнер и закрывает 6379.
3. `bot/podman-compose.yml`: убрать `ports:` у `db` и `redis`. Redis запускать как `redis-server --appendonly yes --requirepass ${REDIS_PASSWORD}` (без пробрасывания порта), Postgres брать из `${POSTGRES_PASSWORD}`. Пароли кладёт владелец в `bot/.env`.
4. Сменить пароль Postgres: `ALTER USER pepito PASSWORD ...`, обновить `DATABASE_URL` и `REDIS_URL` в `bot/.env`.
5. Пересоздать только `db` и `redis` (данные на volume сохраняются), затем перезапустить `bot` и `api`.
6. Аудит БД на закладки: роли (`\du`), функции и триггеры, `pg_stat_activity`, расширения. При сомнениях восстановить из бэкапа.
7. Проверить остальные проекты на сервере на открытые 5432/6379/27017. Решение принимают владельцы этих проектов.
8. Ротировать `BOT_TOKEN` и `GEMINI_API_KEY` превентивно: Redis-контейнер их не видел, но в подконтрольной атакующему сети были `bot` и `api`.

**Готово, когда:** `ss -tlnp` не показывает 5432/6379 на `0.0.0.0`, в `podman top` нет посторонних процессов, healthcheck Redis зелёный, а Redis без пароля отвечает `NOAUTH`.

## 3. Фаза P0: деньги, квоты, сломанная логика

Цель: ни одна оплата не теряется и не начисляется дважды, лимит не списывается за сбой, все кнопки работают.

### P0.1 Платежи не теряются
- **Баг:** `main.py` → `bot.delete_webhook(drop_pending_updates=True)`. Апдейт `successful_payment`, пришедший во время даунтайма, выбрасывается.
- **Фикс:** `drop_pending_updates=False` в `run_bot` и `run_all`.
- **Страховка:** при старте и раз в 15 минут сверка через `getStarTransactions`: каждая входящая транзакция без строки в `payments` начисляется задним числом.
- **Тест:** юнит на сверку; интеграционный тест «оплата во время остановки → после старта Premium выдан».

### P0.2 Идемпотентность и журнал платежей
- **Баг:** у `subscriptions.telegram_payment_charge_id` нет UNIQUE, а проверка устроена как check-then-insert.
- **Фикс:** новая таблица `payments`:
  - поля `id`, `user_id`, `provider (stars|tbank)`, `charge_id UNIQUE`, `provider_charge_id`, `product_code`, `amount`, `currency`, `is_recurring`, `raw JSONB`, `status (paid|refunded)`, `created_at`;
  - в одной транзакции `INSERT … ON CONFLICT (charge_id) DO NOTHING RETURNING id`, и только при вставке продлевается подписка;
  - partial UNIQUE index на `subscriptions.telegram_payment_charge_id WHERE NOT NULL`.
- Миграция Alembic: правка `bot/alembic/` и `bot/app/infrastructure/db/` по Guardrails требует явного «ОК» владельца, и этот документ его фиксирует.

### P0.3 Срок Premium проверяется при каждом доступе
- **Баг:** везде проверяется `usr.is_premium`. Флаг снимает крон раз в сутки (00:05 UTC), поэтому после окончания подписки Premium работает ещё до 24 часов.
- **Фикс:**
  - единая функция `entitlements.is_premium(user, now)` = `subscription_expires_at > now` (флаг остаётся только кешем для админки);
  - заменить все `usr.is_premium` в `app/bot`, `app/api`, `app/scheduler`;
  - `expire_subscriptions` запускать каждые 10 минут.

### P0.4 Pre-checkout и обязательные команды Stars
- `pre_checkout` сверяет `invoice_payload` с каталогом продуктов из `rules.json`, а также `currency` и `total_amount`.
- Добавить `/paysupport` (обязательно для цифровых товаров в Telegram) и `/terms`.
- `refunded_payment` должен работать через `payments`. Пересчёт Premium вынести в один сервис (сейчас код продублирован в handler и в кроне).

### P0.5 Квоты: атомарно и только за успех
- **Баги:**
  - методы `AiService.*` ловят исключения и *возвращают* строку ошибки, поэтому `except` в хендлере не срабатывает и лимит списывается;
  - пользователю уходит текст исключения `<i>{e}</i>` (утечка деталей, ломает HTML, всегда на английском);
  - между `is_allowed()` и `increment()` есть гонка;
  - лимит общий на всё, сутки считаются по UTC.
- **Фикс:**
  1. `AiService` при сбое бросает `AiUnavailableError` и больше не возвращает строку. Исключение выше по стеку превращается в i18n-текст `ai.fallback` без деталей.
  2. `QuotaService.reserve(user, kind)`: Lua-скрипт `INCR`. Если результат больше лимита, сразу `DECR` и отказ. `commit()` после успеха, `release()` (DECR) при сбое. Ключ `quota:{kind}:{tg_id}:{local_date}`, TTL до местной полуночи + 1 час.
  3. Виды квот: `text` (3 в день Free), `media_trial` (1 навсегда, хранится в БД в `users.media_trial_used_at`).
  4. Free-пользователь с исчерпанной пробой медиа получает пейволл **до** скачивания файла и вызова Gemini.
  5. Числа берутся только из `rules.json`: `ai.free_daily_limit: 3`, `ai.free_media_trial: 1`.
- `_get_fallback_plan` / `_get_fallback_week_plan`: при сбое не сохранять шаблонный план как настоящий. Показывать ошибку с кнопкой «Повторить» и не списывать лимит.

### P0.6 Мёртвые хендлеры «Кинолога»
- **Баг:** `process_coach_question` (`menu.py:731`) зарегистрирован без фильтра раньше хендлеров фото, голоса и видео. Он перехватывает такие сообщения и выходит через `return`, поэтому 3 хендлера недостижимы.
- **Фикс:** фильтр `F.text` на текстовый хендлер. Тест: на каждое состояние и тип контента должен срабатывать ровно один хендлер (проверка роутера).

### P0.7 Напоминания и время пользователя
- В боте нельзя выбрать часовой пояс, а планировщик понимает только `UTC±N`.
- **Фикс:**
  - хранить IANA-зону (`Europe/Moscow`) и выбирать её одной кнопкой «🕒 Моё время» (шлёт текущий час и вычисляет смещение) или из топ-6 зон;
  - миграция `UTC+3 → Europe/Moscow` и т.п.;
  - планировщик сравнивает местное время через `zoneinfo`;
  - не слать напоминание, если сегодня уже есть отметка;
  - при `TelegramForbiddenError` ставить флаг `users.blocked_at` и больше не слать.

### P0.8 Застрявшие пользователи и тупики
- 5 пользователей с собакой и `onboarding_completed_at IS NULL`. Одноразовый скрипт: если собака есть, проставить `onboarding_completed_at = pets.created_at`.
- `handle_voice_action`: если собаки нет, сейчас молча `return`. Нужно отвечать и предлагать кнопку «🐶 Добавить».
- Кнопки собрать в реестр: тест обходит все `callback_data` из клавиатур и проверяет, что у каждой есть хендлер.

### P0.9 Event loop и фоновые задачи
- `asyncio.create_task` без ссылки (`_bg_generate_title`, `_bg_refresh_summary`, метрики в `_guard_html`): хранить в `set` и логировать исключения вместо `except: pass`.
- `generate_training_pdf` (fpdf, синхронно) в `app/api/routes.py:1017` и `app/api/v1/routers/training.py:166` обернуть в `asyncio.to_thread`.
- Аудит других синхронных вызовов (Pillow, большие JSON) в хендлерах тем же способом.

### P0.10 Надёжность исполнения
- Уровень `bot`: Sentry обязателен в проде, сейчас включается опционально.
- `ThrottlingMiddleware` и `AiRateLimiter` создают отдельные Redis-клиенты. Нужен один общий пул из контейнера.
- Если Redis недоступен, бот отвечает «техработы, попробуй через минуту», а не падает молча.

**Готово для P0, когда:**
- `bot/judge.sh` и `uv run pytest tests/unit` зелёные;
- новые тесты покрывают P0.1–P0.8;
- ручной прогон оплаты Stars в тестовой среде Telegram (`/test` bot API) выдаёт Premium, повтор апдейта не создаёт второй подписки, refund снимает Premium.

## 4. Фаза P1: монетизация, паспорт, UX, деплой

### P1.1 Каталог продуктов (`rules.json` → `products`)
| code | Тип | Цена ₽ | Цена Stars | Дни |
|---|---|---|---|---|
| `premium_sub_1m` | Stars-подписка, `subscription_period=2592000` | 1490 ₽ (через Т-Банк) | 950 XTR | 30, автопродление |
| `premium_3m` | разово | 3490 ₽ | 2200 XTR | 90 |
| `premium_12m` | разово | 7990 ₽ | 5000 XTR | 365 |

Цены зафиксированы владельцем 2026-11-01. Они лежат в `rules.json` → `products` (сейчас там `stars_1m: 299`, его заменяет этот каталог). Рублёвые цены действуют через Т-Банк, Stars-цены в боте.

- **Stars-подписка:** `createInvoiceLink(subscription_period=2592000)`. Каждое продление приходит как `successful_payment` с `is_recurring=true` и `subscription_expiration_date`, срок берётся из этого поля. Отмена через `editUserStarSubscription` по кнопке «Отменить» в окне Premium.
- **Т-Банк (все три срока):** платёж через Telegram Payments с провайдер-токеном Т-Банк (BotFather). Чеки 54-ФЗ передаются в `provider_data`. Токен и данные кассы даёт владелец, без них фича не включается (feature flag). Odoo-модуль `payment_tinkoff` не используем.
- Пакеты складываются с остатком (`max(now, current_end) + days`), как сейчас.

### P1.2 Пейволл в 1 тап
- При упоре в лимит ответ ИИ-окна заменяется на: короткий текст, кнопку `⭐ Premium` (сразу инвойс подписки, `pay=True`) и кнопку `Тарифы` (окно с 3 вариантами).
- Под каждым бесплатным ответом строка `Осталось 2 из 3 сегодня`, текст в i18n.
- Напоминания о продлении для пакетов (не для подписки): за 3 дня и за 1 день до конца.

### P1.3 Паспорт собаки и память ИИ
- **Модель:**
  - `pets` получает `birth_date`, `weight_kg` (уже есть), `allergies TEXT[]`, `chronic_conditions TEXT[]`, `photo_file_id`, `is_active`;
  - новая таблица `pet_facts` (`pet_id`, `fact`, `source: user|ai`, `created_at`, `deleted_at`).
- **Память:**
  - после каждого ответа ИИ дешёвая модель извлекает новые факты строгим Pydantic (`FactExtraction{facts: list[Fact]}`);
  - в промпт идёт паспорт и последние 20 фактов;
  - окно «🧠 Память» показывает факты, каждый можно удалить кнопкой.
- **Несколько собак:** все `get_pet(user_id)` заменить на `get_active_pet(user_id)`, в шапке окна стоит переключатель `🐶 Рекс ▾`. Лимит берётся из `rules.json`: `pets.free_max: 1`, `pets.premium_max: 3`. При потере Premium лишние собаки становятся read-only, данные не удаляются.

### P1.4 Календарь здоровья (бесплатный)
- Таблица `health_events` (`pet_id`, `kind: vaccine|ticks|worms|custom`, `done_at`, `next_due_at`, `interval_days`, `note`).
- Ввод в 2 тапа: тип → «Сегодня» / «Выбрать дату». Интервалы по умолчанию лежат в `rules.json` (клещи 30 дн, глисты 90 дн, прививка 365 дн).
- Пуши за 3 дня и в день срока, в 10:00 по местному времени. Кнопки: `✅ Сделано` (создаёт следующий цикл) и `⏰ +3 дня`.
- Сезонные пуши: статический календарь в `rules.json` (апрель — клещи, декабрь — реагенты, июль — жара) для северного полушария. Не чаще 1 в 2 недели, отписка в настройках.
- Интеграция с каталогом: под пушем «клещи» кнопка товара из существующего `shop_recommendations`, если он есть.

### P1.5 Трекер
- Таблица `activity_log` (`pet_id`, `kind: task|walk`, `duration_min`, `local_date`).
- **Стрики** считаются по местной дате. Заморозки: Free 1 в неделю, Premium 3 (из `rules.json`), применяются автоматически с пометкой «🧊 заморозка».
- Вечерний пуш (настраиваемо, по умолчанию 20:00) приходит, только если сегодня пусто.
- **Прогулки:** кнопки `15`, `30`, `60 мин` или голосом («погуляли полчаса»), голос разбирает существующий `detect_training_intent` с расширением схемы.
- **Ачивки:** 7 / 30 / 100 дней, 10 прогулок, первая освоенная команда. При получении приходит карточка (P1.7).
- **Недельный отчёт:** воскресенье 19:00 по местному времени вместо общего 18:00 UTC.

### P1.6 Онбординг за 4 тапа
1. «Как зовут?» (текст)
2. Возраст: `Щенок` / `До 3 лет` / `3–7 лет` / `7+`
3. Порода: топ-8 кнопок + `Другая` + `📷 Фото`. Фото разбирает Gemini (Pydantic `BreedGuess{breed, confidence}`), владелец подтверждает. Проба фото на онбординге не тратит `media_trial`.
4. Цель: `Послушание` / `Поведение` / `Щенок` / `Активность`

Финал: паспорт + первый план + главное окно. Остальное паспорт добирает по ходу, из диалогов. Старый ИИ-диалог онбординга удаляется.

### P1.7 PNG-карточки для Stories
- Шаблоны HTML/CSS 1080×1920 лежат в `app/cards/templates/`: стрик, ачивка, паспорт, итоги недели.
- Рендер **без браузера**. Кандидат подбирается на старте P1.7 через `tool-discovery` (WeasyPrint→PNG / resvg / takumi). Критерии: < 100 МБ RAM, поддержка flexbox и веб-шрифтов, активная разработка. Ставится через `uv`, рендер идёт в `asyncio.to_thread`.
- Кнопка `📤 В Stories`: `sendPhoto` + deep-link на шаринг.

### P1.8 Строгий разбор медиа
- Фото и голос в «Кинологе» и в главном окне возвращают `MediaVerdict{summary, urgency: low|vet_soon|vet_now, steps: list[str] (≤5), disclaimer}` (Pydantic, `extra="forbid"`). После 2 неудач выбрасывается `AiUnavailableError` (P0.5).
- `urgency=vet_now` всегда даёт красный блок «К ветеринару сегодня», и он не урезается лимитом символов.

### P1.9 Single-Window меню
- В `users` добавляется `ui_message_id`. Все экраны рендерятся через `edit_message_text` этого сообщения. Если сообщение недоступно (старше 48 ч или удалено), отправляется новое и id перезаписывается.
- `/start` и `/menu` удаляют старое окно и создают новое. Спиннер «⌛️» больше не отправляется отдельным сообщением.
- **Сообщения пользователя не удаляем.** Ответ ИИ приходит отдельным сообщением в истории, а окно меню обновляется ниже (переотправка, чтобы окно было последним).
- Кнопки до 14 символов во всех 6 локалях, главное меню не больше 6 кнопок. Проверяет unit-тест по всем `*.btn` ключам.
- Главное окно: `🏋️ План`, `🧑‍🏫 Кинолог`, `🩺 Здоровье`, `🔥 Трекер`, `🐶 Паспорт`, `⚙️ Ещё`.

### P1.10 Тон и тексты
- Обращение на «ты», короткие фразы, без канцелярита («осуществить», «в рамках», «данный») и ИИ-штампов («Отличный вопрос!», «Важно отметить»).
- Чек-лист humanizer-ru применяется к `ru.py` и системным промптам `ai_service.py`. Стоп-слова лежат в `rules.json` → `copy.banned_ru`, их проверяют unit-тест (строки i18n) и `eval/promptfooconfig.yaml` (ответы ИИ).
- Остальные локали переводятся с обновлённого RU.

### P1.11 Деплой: Podman Quadlet + systemd
- Файлы `deploy/quadlet/pepito-{db,redis,bot,api}.container` и `pepito.network`.
- `Restart=always`, `HealthCmd`, `HealthOnFailure=kill`, `Notify=healthy`.
- Секреты через `podman secret`, а не `.env`. Наружу публикуется только `api` через `npm_network`, без `PublishPort` для db и redis.
- `bot/judge.sh` добавляет проверку, что в compose/quadlet нет `0.0.0.0:5432|6379`.
- Бэкап: systemd timer `pg_dump` раз в сутки, ротация 7 копий.
- Миграции через отдельный oneshot unit `pepito-migrate.service` перед `bot`.

**Готово для P1, когда:**
- e2e-сценарий «новый пользователь → 4 тапа → план → 3 вопроса → пейволл → оплата Stars (тестовая среда) → Premium → медиа-разбор → карточка» проходит без лишних сообщений в чате;
- после `systemctl restart pepito-bot` бот поднимается сам, апдейты не теряются.

## 6. Порядок работ и зависимости

```
P0-SEC (ручное/с ОК)
  └─ P0.1 → P0.2 → P0.3 → P0.4        (деньги)
  └─ P0.5 → P0.6 → P0.8               (квоты, мёртвые хендлеры)
  └─ P0.7, P0.9, P0.10                (время, event loop, надёжность)
       └─ P1.11 деплой (можно параллельно с P1.x)
       └─ P1.1 → P1.2                 (продукты, пейволл)
       └─ P1.3 → P1.4 → P1.5 → P1.7   (паспорт → здоровье → трекер → карточки)
       └─ P1.6, P1.8, P1.9, P1.10     (онбординг, медиа, меню, тексты)
            └─ P2
```

Правила исполнения (из `CLAUDE.md`):
- TDD на каждый пункт;
- продуктовые числа только в `rules.json`;
- `uv` / `podman`;
- без `git commit` / `push` без ОК владельца;
- изменения в `bot/alembic/`, `bot/app/infrastructure/db/`, compose и `.env` только по явной просьбе. Этот документ — согласованный план, но на каждую миграцию берём отдельное «ОК».
